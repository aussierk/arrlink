# Exact-pinned (direct + full transitive closure), not open ranges, so a
# `docker compose build` today resolves to the identical set every time --
# previously (">=" lower bounds only) every build could silently pull a
# different, unreviewed transitive version, including a compromised or
# vulnerable release, with nothing to diff. Regenerate after a deliberate
# upgrade with:
#   pip install --upgrade fastapi 'uvicorn[standard]' httpx pydantic-settings \
#       python-multipart argon2-cffi
#   pip freeze | grep -viE '^(pip|setuptools|wheel)=='
# and re-pin the direct deps' extras/bounds below by hand -- an extras-only
# dependency (e.g. uvicorn[standard]'s pyyaml) doesn't always show up the
# same way in every `pip freeze` capture, so also run
# `pip install --dry-run -r requirements.txt` against the *result* and
# confirm every line says "already satisfied" at the exact pinned version,
# with nothing pulled in unpinned (this is exactly how the missing pyyaml
# pin below was caught after the first pass of this file missed it).
# NOTE: not hash-pinned (no `--hash=...` per line, e.g. via
# `pip-compile --generate-hashes`) -- that needs network access to fetch
# per-platform wheel hashes, which wasn't available when this was generated.
# Hash-pinning would be a stronger guarantee (rejects a tampered artifact
# even at an already-pinned version) and is worth adding if this becomes a
# concern; exact-version pinning alone already closes the "different build,
# different code" reproducibility gap this was written to fix.
